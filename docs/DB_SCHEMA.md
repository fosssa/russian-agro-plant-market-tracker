# Схема базы данных

В этом проекте используется база данных SQLite, управляемая через SQLAlchemy (см. `backend/db.py`).

Текущая схема базы данных включает три основные таблицы:

- `organizations` — организации / источники данных
- `products` — аграрные продукты и показатели
- `records` — временные ряды значений по продуктам

Все внешние ключи настроены с включёнными ограничениями (`PRAGMA foreign_keys=ON` для SQLite).

---

## Таблица `organizations`

**Назначение:** источники данных/организации, откуда поступает аграрная информация.

| Поле      | Тип      | Ограничения                         | Описание                          |
|-----------|----------|-------------------------------------|-----------------------------------|
| `id`      | Integer  | PK, autoinкrement, `index=True`     | Уникальный идентификатор записи   |
| `name`    | String   | `nullable=False`                    | Название организации              |
| `link`    | String   | `nullable=True`                     | Ссылка на источник данных         |
| `location`| String   | `nullable=True`                     | Географическое расположение       |

**Связи:**

- Один `Organization` имеет много `Product` (`Organization.products`).
- При удалении организации её продукты удаляются каскадно (`cascade="all, delete-orphan"`).

---

## Таблица `products`

**Назначение:** аграрные продукты/показатели, по которым собирается статистика.

| Поле             | Тип                             | Ограничения                         | Описание                                      |
|------------------|----------------------------------|-------------------------------------|-----------------------------------------------|
| `id`             | Integer                          | PK, autoincrement, `index=True`     | Уникальный идентификатор продукта             |
| `name`           | String                           | `nullable=False`                    | Название продукта/показателя                  |
| `type`           | Enum(`ProductType`, text-based)  | `nullable=False`                    | Тип продукта/показателя (см. Enum ниже)       |
| `organization_id`| Integer (FK → `organizations.id`)| `nullable=False`                    | Связь с источником/организацией               |
| `link`           | String                           | `nullable=True`                     | Ссылка на страницу с данными по продукту      |

Поле `type` хранится как строковый Enum (`native_enum=False`) с возможными значениями из `ProductType`:

- `"Валовой сбор"` (`GROSS_HARVEST`)
- `"Цена"` (`PRICE`)
- `"Средняя цена"` (`AVERAGE_PRICE`)
- `"Фьючерс"` (`FUTURES`)
- `"Общая выручка"` (`TOTAL_REVENUE`)
- `"Объём реализации"` (`SALES_VOLUME`)
- `"Площадь земель"` (`LAND_AREA`)

**Связи:**

- Многие `Product` принадлежат одному `Organization` (`Product.organization`).
- Один `Product` имеет много `Record` (`Product.records`).
- При удалении продукта его записи удаляются каскадно (`cascade="all, delete-orphan"`).

---

## Таблица `records`

**Назначение:** временные ряды значений по продуктам.

| Поле        | Тип        | Ограничения                             | Описание                                        |
|-------------|------------|-----------------------------------------|-------------------------------------------------|
| `id`        | Integer    | PK, autoincrement, `index=True`         | Уникальный идентификатор записи                 |
| `timestamp` | DateTime   | `nullable=False`, `unique=True`, index  | Метка времени наблюдения                        |
| `value`     | Float      | `nullable=False`                        | Числовое значение показателя                    |
| `product_id`| Integer (FK → `products.id`)| `nullable=False`          | Ссылка на продукт, к которому относится запись  |

**Особенности:**

- Для `timestamp` установлены `unique=True` и `index=True`, что гарантирует уникальность отметки времени в таблице.

**Связи:**

- Многие `Record` принадлежат одному `Product` (`Record.product`).

---

## Сводка связей (ER-схема в текстовом виде)

- `organizations (1) ──< (N) products`
- `products (1) ──< (N) records`

Итого: одна организация может иметь множество продуктов, каждый продукт — множество временных записей.

При изменении моделей в `backend/models/db_models.py` не забудьте обновить это описание, чтобы схема оставалась актуальной.
